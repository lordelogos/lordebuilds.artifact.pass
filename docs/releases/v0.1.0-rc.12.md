# ArtifactPass v0.1.0-rc.12 release candidate

Date: 2026-08-29

Status: replacement candidate for multi-workspace connection and publishing tests.

## Why this candidate exists

RC11 launched the plugin MCP from its installed cache directory. Codex did not expose the active workspace to that process, so ArtifactPass could select an unrelated active profile and reject a valid artifact as outside the approved workspace roots.

## What changed

ArtifactPass now selects the deployment from the operation itself:

- connection and status use the absolute workspace path supplied by the share skill;
- publishing uses the absolute artifact path;
- reading uses the ArtifactPass link origin.

The approved-root check remains mandatory. The change selects the correct configured root before enforcing it; it does not broaden file access.

## Qualification

The candidate must pass the workspace-routing regression tests, package and plugin checks, packed-install proof, release check, and a real staging publish launched from a plugin cache-style working directory.

## Publishing

The candidate is published from the immutable `v0.1.0-rc.12` tag by `publish-candidate.yml` under the npm `rc` tag.
