# ArtifactPass v0.1.11

Status: stable release promoted from the qualified `v0.1.11-rc.2` candidate.

## What changed

- ArtifactPass can be installed once and approve the current project from the agent flow when a share is first attempted.
- The original share request resumes after approval without another terminal command or agent restart.
- `artifactpass workspace list` and `artifactpass workspace remove` make project access visible and revocable.
- ArtifactPass.com returns a controlled, protocol-valid `503` with a request ID when its Pages-to-Worker service binding fails instead of exposing Cloudflare Error 1101.
- Failure logs contain only allowlisted request metadata and do not expose exception messages or artifact paths.
- The MCP client and Wrangler dependency chains are updated past the vulnerabilities caught by the release audit.

## Qualification

The release passed the complete release gate and packed-install proof. The exact `v0.1.11-rc.2` package was published to npm, deployed to staging as Cloudflare Worker version `edda3696-b6af-459f-bc3e-cf6230d9e497`, and passed health, protected-upload, Google OAuth-start, and GitHub OAuth-start checks. The Pages fix was deployed to an isolated preview and passed static-page, application health, and protected-upload checks. Stable package contents must match that RC after version-only normalization.
