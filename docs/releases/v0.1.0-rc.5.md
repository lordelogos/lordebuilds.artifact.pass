# ArtifactPass v0.1.0-rc.5 release candidate

Date: 2026-08-27

Status: staging candidate for clean second-PC testing.

## What changed

- Installation now registers the ArtifactPass plugin, MCP tools, and Agent Skills without opening a browser or authenticating.
- A disconnected agent can invoke Connect ArtifactPass, complete Google or GitHub approval, and publish in the same MCP session without reinstalling or restarting.
- Connection state recovers after token revocation, concurrent connection attempts share one authorization, and failed credential persistence revokes the issued server token.
- Upgrades remove only the old installer-owned standalone MCP registration while preserving rollback.
- Install receipt v3 records the four-tool connection-aware MCP contract while v1 and v2 remain immutable.
- Hosted publication retries remain compatible with artifacts created before the stable publisher-identity change.

## Qualification

The candidate passes workspace lint and typechecking, focused agent bridge, setup CLI, and Worker tests, Codex and Claude installed-host conformance, and the packed one-command installation test.

The second-PC test must start from a clean test folder with no ArtifactPass installation state. Installation must remain disconnected. The first agent publish request must trigger ArtifactPass sign-in and complete in the same agent session.

## Publishing

The candidate is published from the immutable `v0.1.0-rc.5` tag by `publish-candidate.yml`. GitHub OIDC trusted publishing supplies the short-lived registry credential and publishes the reviewed archive under the npm `rc` tag.
