# ArtifactPass v0.1.0-rc.7 release candidate

Date: 2026-08-28

Status: staging candidate for clean second-PC testing.

## Why this candidate exists

An installed workspace could not change its ArtifactPass deployment through the normal setup experience. The only available workaround required another flags-heavy install command or manual config editing.

## What changed

- Initial setup now asks whether the current workspace uses public ArtifactPass or an organization deployment.
- Rerunning the base command reopens that deployment choice without authenticating.
- `artifactpass configure` changes the current workspace without reinstalling or editing config files.
- Personal and company workspaces can select different deployments on the same machine.
- Existing profiles and origin-bound credentials remain isolated and are not silently reused for a different deployment.
- The MCP loads the deployment bound to the workspace where the agent session starts.

## Qualification

The candidate must pass the complete release check, packed-install check, and an isolated interactive CLI rehearsal that proves initial setup and later reconfiguration do not open a browser. Clean second-PC testing then verifies that connection begins only when the agent invokes `connect_artifactpass`.

## Publishing

The candidate is published from the immutable `v0.1.0-rc.7` tag by `publish-candidate.yml`. GitHub OIDC trusted publishing supplies the short-lived registry credential and publishes the reviewed archive under the npm `rc` tag.
