# ArtifactPass v0.1.0-rc.18 release candidate

Date: 2026-09-12

Status: production-release-path rehearsal candidate.

## Why this candidate exists

RC18 rehearses the release machinery that will promote the first stable ArtifactPass package without risking replacement production storage, an uncontained Worker, or an OAuth deployment with unreviewed intermediate code.

## What changed

- GitHub OAuth now binds authorization and callback with S256 PKCE while preserving state and return-target validation.
- Production deployment has an explicit existing-resource mode that refuses to create or substitute the Worker, D1 database, R2 bucket, custom domain, or Access application.
- Production preflight requires the exact remote inventory and refuses any pending migration set other than `0009-cleanup-indexes.sql`.
- OAuth secrets and reviewed Worker code now enter one deployment through Wrangler's secrets file instead of a separate secret-only deployment.
- Every production Worker ingress is inventoried, and public promotion refuses unapproved custom domains, routes, `workers.dev`, or preview access.
- Public activation is a separate reversible operation. Failed verification removes the temporary bypass policy and restores Access containment.
- Capability reads now have an explicit per-IP limit, and capability paths are redacted from unexpected-error telemetry.
- Operations documentation now records all nine migrations and the public abuse thresholds.

## Qualification

This candidate must pass the complete release gate, packed installation, staging deployment, both staging OAuth providers, focused browser and agent sharing, exact migration and lifecycle checks, then a previous-Worker rollback and candidate roll-forward rehearsal.
