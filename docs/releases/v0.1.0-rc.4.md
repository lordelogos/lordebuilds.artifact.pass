# ArtifactPass v0.1.0-rc.4 release candidate

Date: 2026-08-27

Status: staging-qualified candidate for fresh-install and cross-machine testing.

## What changed

- Public ArtifactPass authentication now uses Google or GitHub login instead of exposing Cloudflare administration to end users.
- Installation registers the shared MCP bridge and Agent Skills without authenticating; workspace connection happens only when the user explicitly runs the connect flow.
- Public uploads and agent publishing share bounded identity and network quotas.
- Deployment tooling reuses explicitly named staging resources and verifies the intended Cloudflare account, zone, Worker, D1 database, and R2 bucket before mutation.
- The `read_artifact` MCP schema now advertises and enforces the protocol's 65,536-byte maximum source chunk size.

## Staging qualification

The candidate was rehearsed against `staging.artifactpass.com` with Google sign-in, human upload, agent publish and exact-byte read, shared quota enforcement, and a disposable device connection. The disposable connection returned the expected `artifact:create` scope, was revoked, and left the original local profile intact.

This staging evidence does not replace the fresh-install test. The immutable npm candidate must still be installed on the second PC with no repository checkout or existing ArtifactPass state, connected to staging, and exercised through a real agent host.

## Publishing

The candidate is published from the immutable `v0.1.0-rc.4` tag by `publish-candidate.yml`. GitHub OIDC trusted publishing supplies the short-lived registry credential; the workflow validates, builds, packs, and uploads the reviewed archive under the npm `rc` tag.
