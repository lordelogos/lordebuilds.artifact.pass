# ArtifactPass v0.1.0-rc.2 release candidate

Date: 2026-08-17

Status: locally verified; external publication and deployment gates are staged, not released.

## What changed

- The public product, package, executable, plugin, marketplace, MCP registration key, and skill namespace are now ArtifactPass / `artifactpass`.
- `pnpm dlx artifactpass` is the primary installation path. It authorizes the current workspace, detects supported hosts, installs the canonical portable MCP and Agent Skills bundle, reuses a valid credential, verifies both tools and skills, and emits a private versioned receipt.
- Legacy config, environment, keychain, signing-key, and publication-journal state migrate under a recoverable lock without changing pending share identity or deleting the old state prematurely.
- Codex and Claude are thin registration adapters over the same portable files. Other compatible systems receive exact MCP and Agent Skills registration paths.
- Active browser, CLI, bridge, plugin, and documentation copy now uses ArtifactPass.

## Compatibility held stable

The release does not rename or replace the production Worker, D1 database, R2 bucket, Access application/policy, bindings, migrations, health service ID, MCP tool names, signed PDF qualifiers, publication commitments, or existing share URLs. The retained identifiers are documented and regression-tested.

## Local evidence

- Source and packed installer scenarios cover clean install, migration, credential reuse, browser fallback, portable fallback, rerun repair, conflict, crash resume, concurrent lock, and rollback after MCP failure.
- Isolated Codex and Claude homes install and launch the same shared runtime and skills bytes and negotiate `publish_artifact` plus `read_artifact`.
- Worker, bridge, setup, local-demo, branding, type, lint, package, license, dependency, and secret gates are included in the final release check.
- `release/manifest.json` records the exact commit, package identities, artifact digests, and deliberately preserved production identifiers. `release/checksums.txt` contains the archive SHA-256 values.

## External approval gates

The following actions remain separate and must not be inferred from this candidate:

1. Publish the unscoped `artifactpass` package and verify its registry digest against the reviewed tarball.
2. Rename the private GitHub repository from `lordelogos/lordebuilds.artifacts.share` to `lordelogos/artifactpass`, preserving private visibility and `main`.
3. Generate and approve a fresh Cloudflare state-bound manifest whose diff changes only the reviewed Worker bundle and active branding copy.
4. Run the registry-based install and two-agent Markdown, HTML, human-PDF, controlled-PDF, old-link, and migrated-host checks against `https://artifactpass.com`.

## Known release debt

The working upload, approval, and share pages have ArtifactPass copy but have not received the full visual redesign requested for the public release. Behavioral evals for installation, skills, MCP tool choice, autonomous handoff, and cross-agent fidelity are the next roadmap phase after this release candidate boundary.
