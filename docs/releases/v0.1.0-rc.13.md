# ArtifactPass v0.1.0-rc.13 release candidate

Date: 2026-09-03

Status: not published. Superseded by RC14.

## Why this candidate exists

RC12 allowed the connection tools to run without an explicit workspace path. A globally installed MCP could therefore select the wrong configured deployment, including production when the active project was configured for staging.

## What changed

ArtifactPass now requires an absolute `workspace_path` for both connection operations:

- `connection_status` resolves the deployment configured for that workspace;
- `connect_artifactpass` starts authorization against that same deployment;
- calls without a workspace path fail before any browser authorization begins.

The approved-root boundary remains unchanged. This release removes an ambiguous fallback rather than broadening access.

## Qualification

The candidate must pass the workspace-routing regression tests, portable MCP contract, package and plugin checks, packed-install proof, and the complete release gate.

## Publishing

The immutable `v0.1.0-rc.13` tag passed every release gate, but npm rejected the explicit provenance bundle because the source repository was private. No RC13 package was published. RC14 retains the same product fix and corrects the publishing workflow without moving this tag.
